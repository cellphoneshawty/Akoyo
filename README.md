## 💡 What is Akoyo?

You love a song on Spotify — but the **remix** that's even better is only on SoundCloud. And the live version is on YouTube Music.

Normally that means jumping between three apps. **With Akoyo, you don't have to.**

Akoyo brings all your music services together. Search them all at once, like tracks from anywhere, and listen to everything in one player — right in your browser.

> 🎯 **Listen to what you want, where you want.**
> If a song isn't on one platform, it's on another — and Akoyo will find it.

---

## 🚀 Get started in 2 minutes

> ⚠️ **Akoyo is still in development.** The first release isn't out yet — this is how it will work.

1. 📥 **Download** Akoyo for Windows from the [Releases](https://github.com/cellphoneshawty/Akoyo/releases) page
2. ▶️ **Open it** — Akoyo starts and opens in your browser by itself
3. 👤 **Create an account**
4. 🔗 **Connect your music services** — just log in, Akoyo guides you step by step
5. 🎶 **Enjoy your music**

That's it. Nothing else to install, nothing to configure.

## 💾 Offline music — you decide

Choose how much music Akoyo keeps on your computer:

- ⏮️ **The first songs** of your library — for example, the first 100
- ⏭️ **The latest songs** you liked or listened to
- 📌 **Favourites** you pinned — these are never removed
- 📦 **A size limit** — for example, no more than 5 GB
- 🧹 **Nothing at all** — songs are removed when you close Akoyo, so your disk stays clean

You can change this anytime in **Settings**.

## 👨‍👩‍👧 Using Akoyo at home

Akoyo runs on one computer, but everyone at home can use it — from a phone, a laptop or a tablet.

1. Open **Settings → Sharing** on the computer where Akoyo is running
2. Open the address you see there in a browser on any other device at home
3. Each person creates their own account and connects their own services

Akoyo uses your accounts the way a normal music app would — for listening to your own music. That said, Akoyo isn't an official app of any of these services, so we can't promise anything on their behalf.

# 🛠️ For developers

*Everything below is technical. You don't need any of it to use Akoyo.*

### Tech stack

| Part | Technology |
|---|---|
| 🦀 Backend | Rust — Axum, Tokio |
| 🎨 Frontend | Svelte, embedded into the binary |
| 🗄️ Storage | SQLite (bundled), single local file |
| 📦 Distribution | One self-contained executable, no runtime dependencies, no Docker |

### How it works

- Akoyo is a **self-hosted** web server. On launch it opens `http://localhost:<port>` in the default browser and sits in the system tray.
- Each streaming service is implemented as a separate **adapter** behind a common interface (search, library, stream). Unofficial APIs break from time to time — isolating them keeps the rest of the app working and makes fixes local.
- Audio is **proxied through the backend**, so the browser just plays a regular `<audio>` stream. This avoids CORS issues and expiring stream URLs, and lets caching work transparently.
- **YouTube Music** uses an InnerTube client, with a bundled `yt-dlp` as a fallback stream extractor.
- **Spotify** signs in the way open-source clients such as [librespot](https://github.com/librespot-org/librespot) / [spotifyd](https://github.com/Spotifyd/spotifyd) do, so no developer app or client ID is required. Spotify audio is DRM-protected and is never cached.
- **Track matching** across platforms uses ISRC where available, falling back to fuzzy matching on artist, title and duration. Remixes are stored as separate tracks, not as alternative sources of the original.
- **Temporary cache mode:** browsers can't reliably report when they close, so the cache is cleared after a period with no activity from the client (heartbeat timeout) and on server start.
- Streaming service credentials are **encrypted at rest** in the local database.

### Building from source

You'll need [Rust](https://rustup.rs) (stable) and [Node.js](https://nodejs.org) 20+.

```bash
# 1. Build the web UI (it gets embedded into the executable)
cd web
npm install
npm run build
cd ..

# 2. Build and run Akoyo
cargo run              # debug build, with a console window
cargo build --release  # target/release/akoyo.exe — the file that ships
```

Working on the UI? Keep `cargo run` going and start `npm run dev` in `web/` — Vite serves the UI with hot reload and forwards `/api` to the backend on port 7700.

**Useful environment variables**

| Variable | What it does |
|---|---|
| `AKOYO_DATA_DIR` | Where to keep the database, settings and logs. Default: `%LOCALAPPDATA%\Akoyo` |
| `AKOYO_LOG` | Log filter, e.g. `debug` or `akoyo=trace` |

**Project layout**

```
src/            Rust backend (Axum server, auth, tray icon)
migrations/     SQLite schema, applied automatically on start
web/            Svelte web UI, built into web/dist and embedded into the binary
```
